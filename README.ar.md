أمران لا يقوم بهما وكيل البرمجة لديك نيابة عنك، يُنجَزان وأنت بعيد عن لوحة المفاتيح.

- **إبقاء النافذة مفتوحة** — تُفتح نافذة استخدام جديدة فور إعادة تعيين السابقة، حتى لو لم يكن أحد يعمل، فتجد عند عودتك حصة كاملة قيد الاستخدام بالفعل.
- **التنبيه** — حين يتوقف ذلك عن العمل يخبرك: عبر Bark أو ntfy أو البريد الإلكتروني أو أي قناة أخرى تختار وصلها.

أما استئناف الجلسة بعد بلوغ حد الاستخدام فصار الوكلاء أنفسهم يقومون به، ولذلك يتركه Claude Plus لهم.

## الوكلاء

يقيس كل من Claude Code وCodex وAntigravity الاشتراك بالطريقة نفسها: نافذة قصيرة تبدأ من أول طلب لك، وفوقها نافذة أطول. ويُبقي Claude Plus مفتوحًا ما هو مثبَّت لديك منها.

| الوكيل | من أين تأتي حدوده | ما يتغيّر في إعداداته |
|--------|-------------------|------------------------|
| Claude Code | شريط الحالة، مع كل تحديث | مدخل واحد في شريط الحالة |
| Codex | سجلات جلساته، تُقرأ عند الحاجة | لا شيء |
| Antigravity | شريط الحالة، مع كل تحديث | مدخل واحد في شريط الحالة |

لكل وكيل نافذته وجدولته وتنبيهاته الخاصة، ولا شيء مشترك بينها. وإضافة وكيل آخر ملف واحد فقط — انظر [docs/PROVIDERS.md](docs/PROVIDERS.md). ولتصريح الواجهة بطريقة القياس سبب: ففي Kimi Code تحدّ النافذة القصيرة من معدّل الطلبات بدل أن تقيس حصة، وGrok Build له رصيد أسبوعي واحد بلا نافذة قصيرة — وفي الحالتين لا توجد نافذة يمكن إبقاؤها مفتوحة.

## ما الفائدة

**وقت فتح النافذة هو ما يحدد وقت انتهائها.** تبدأ النافذة من أول طلب لك، لا من ساعة ثابتة. ومثالها نافذة الخمس ساعات: ابدأ العمل في التاسعة صباحًا فتمتد من 9:00 إلى 14:00؛ وإذا استنفدت الحصة عند 11:00 بقيت محجوبًا حتى 14:00. أما لو كان طلب صغير قد فتح النافذة عند 6:00، لانتهت عند 11:00 — أي في اللحظة نفسها التي تنفد فيها حصتك — وكانت حصة جديدة في انتظارك. ومع نافذة تعمل دائمًا، تكون هناك نافذة قيد التشغيل حين تبدأ: فما تبقى منها حصة كانت ستضيع لولا ذلك، والحصة الجديدة على بُعد نافذة واحدة على الأكثر، وغالبًا أقل بكثير.

**يوم العمل يتسع لعدد أكبر من النوافذ حين تبدأ مبكرًا.** ابدأ في التاسعة فتمتد النافذتان من 9:00 إلى 14:00 ومن 14:00 إلى 19:00: اثنتان حتى نهاية دوامك. أما لو فُتحت واحدة عند 6:00، لغطّى اليوم 6:00-11:00 و11:00-16:00 و16:00-21:00 — ثلاث نوافذ، في الساعات نفسها أمام المكتب. ولهذا وُجد الوقت الثابت المذكور أدناه.

**معرفة متى توقف عن إفادتك.** إبقاء النوافذ مفتوحة لا يعمل إلا ما دام تسجيل الدخول صالحًا والمجدول يعمل؛ فإذا توقف أيٌّ منهما لم يحدث شيء على الإطلاق. ينتبه Claude Plus إلى كلتا الحالتين ويخبرك بها، بدل أن يفشل صامتًا طوال عطلة نهاية الأسبوع.

## المتطلبات

نظام Linux مع `jq` و`at` (مع تشغيل `atd`) و`flock` و`timeout` و`date` من GNU، وواحد على الأقل من `claude` أو `codex` أو `agy`.

```bash
sudo systemctl enable --now atd
```

## التثبيت

```bash
npx @claude-plus/claude-plus
```

أو من نسخة مستنسخة:

```bash
git clone https://github.com/MrJasonZhou/claude-plus.git
cd claude-plus
bash install-claude-plus.sh
```

لكل وكيل لديه شريط حالة، يغلّف المثبِّت الشريط الموجود لديك أصلًا، فيبقى ظاهرًا كما كان تمامًا؛ وهذا هو التغيير الوحيد في إعدادات ذلك الوكيل، ويُحفظ كل ملف إعدادات احتياطيًا قبل ذلك. أما Codex فلا يحتاج أي إعداد. وإعادة تشغيل المثبِّت ترقية نظيفة لا نسخة ثانية، وتحتفظ لكل وكيل بتشغيله المجدول التالي وحالته، وبأداة التنبيه الخاصة بك.

## الاستخدام

في الاستعمال اليومي لا شيء يحتاج إلى تشغيل — فهو يعمل وحده. وحين تريد الاطلاع:

```bash
~/.claude/claude-plus/claude-plus.sh status    # لكل وكيل: النافذة والجدولة والإخفاقات
~/.claude/claude-plus/claude-plus.sh providers # أي الوكلاء مثبَّت
tail -f ~/.claude/claude-plus/claude-plus.log  # ما الذي كان يفعله
```

## الفتح في وقت ثابت

افتراضيًا تُفتح النافذة فور إعادة تعيين سابقتها، فتتبع السلسلة الوقت الذي نفدت فيه حصتك آخر مرة. ولتثبيتها على وقت محدد من اليوم:

```bash
~/.claude/claude-plus/claude-plus.sh anchor 06:00   # الفتح عند 06:00
~/.claude/claude-plus/claude-plus.sh anchor         # عرض الإعداد الحالي
~/.claude/claude-plus/claude-plus.sh anchor off     # العودة إلى الفتح في أقرب وقت
```

أما النافذة التي ستمتد عبر ذلك الوقت فتنتظره بدلًا من ذلك: النافذة المقرَّرة عند 03:00 كانت ستغطي 03:00-08:00 وتبتلع 06:00، لذا تُفتح عند 06:00. وبذلك تبقى الساعات التي تسبق الوقت المحدد بلا نافذة — وإن عملت فيها، فإن أول طلب منك يفتح واحدة كالمعتاد. ويسري هذا الإعداد على كل الوكلاء.

## التنبيهات

يبقى Claude Plus صامتًا ما لم يكن هناك ما يستدعي تدخلك، ولا يبلغك إلا بأربعة أمور:

| | |
|---|---|
| **تسجيل الخروج** | انتهت صلاحية دخول أحد الوكلاء، فلا يمكن فتح شيء له حتى تسجل الدخول من جديد |
| **فشل متكرر** | فشلت عدة عمليات إحماء متتالية لأحد الوكلاء |
| **توقف المجدول** | تأخر تشغيل مجدول كثيرًا عن موعده، فلا تُبقى أي نافذة مفتوحة؛ وغالبًا يكون `atd` غير مشغّل |
| **العودة إلى الوضع الطبيعي** | تعافى من أيٍّ من الحالات أعلاه |

يُبلَّغ عن كل أمر مرة واحدة لكل وكيل، لا مع كل محاولة إعادة، فمشكلة تقع أثناء الليل تكلفك رسالة واحدة. أما حدود الاستخدام نفسها فلا يُعلَن عنها أبدًا: فهي أمر معتاد، والوكلاء يستأنفون بعدها من تلقاء أنفسهم.

ولاختيار الطريقة التي يصلك بها الخبر، انسخ أحد النماذج واملأ مفتاحك أو خادمك:

```bash
cd ~/.claude/claude-plus
cp notify/bark.sh.sample notify.sh      # أو ntfy.sh.sample أو email.sh.sample
chmod +x notify.sh                      # استخدم 700 لنموذج البريد لأنه يحتوي على كلمة مرور
$EDITOR notify.sh
./claude-plus.sh notify-test            # تأكد من وصوله إليك
```

أداة التنبيه ليست سوى ملف تنفيذي يستقبل `CP_EVENT` و`CP_MESSAGE` و`CP_HOST`، لذا فإن Telegram أو Slack أو خطاف ويب أو `mail` كلها مسألة إعادة كتابة سطر واحد. ونسختك تبقى بعد إعادة التثبيت.

## الملفات

كل شيء داخل `~/.claude/claude-plus/`:

| | |
|---|---|
| `claude-plus.sh` | السكربت نفسه |
| `providers/` | ملف واحد لكل وكيل |
| `state/<الوكيل>/` | نافذة ذلك الوكيل وجدولته وحالة تنبيهاته |
| `notify.sh` | أداة التنبيه الخاصة بك بعد إعدادها |
| `notify/` | نماذج للنسخ منها |
| `anchor` | وقت فتح النوافذ، إن حددته |
| `claude-plus.log` | ما الذي كان يفعله |

## إلغاء التثبيت

```bash
npx @claude-plus/claude-plus uninstall
```

أو من نسخة مستنسخة: `bash install-claude-plus.sh uninstall`.

يعدّل إعدادات كل وكيل في مكانها ولا يزيل منها إلا ما أضافه Claude Plus: يعود شريط الحالة الذي كان لديك، وتبقى كل الإعدادات الأخرى كما هي تمامًا — بما فيها ما أُضيف بعد التثبيت. وتُلغى المهام المجدولة ويُحذف `~/.claude/claude-plus/`، ومعه ملف `notify.sh` الخاص بك. وتشغيله مرة ثانية لا يسبب أي ضرر.

وإذا قام برنامج آخر لاحقًا بتغليف أحد أشرطة الحالة من فوق Claude Plus، فإن إلغاء التثبيت لن يعطّله. يُترك سكربت تمرير صغير كي يستمر ذلك البرنامج في العمل، ويخبرك المُلغي بذلك؛ شغّله مرة أخرى حين لا يعود هناك ما يحتاجه. والترقية في الحالة نفسها تبقى داخل سلسلة ذلك البرنامج بدل أن تغلّفه بدورها.

وتُحفظ بجانب كل ملف إعدادات نسخة منه كما كان قبيل إلغاء التثبيت مباشرة، وكذلك النسخ التي أُنشئت عند التثبيت، تحسبًا لحاجتك يومًا إلى الرجوع يدويًا.
